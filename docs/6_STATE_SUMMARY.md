- **T07:** Added StockService with receive/issue/adjust/transfer. All writes go through one conditional UPDATE (never below zero) plus an immutable ledger row, with row locks taken in a consistent order to avoid deadlocks. A 25-way race test proves no overselling, and post-commit observers enable realtime and alerts.
- **T08:** Added supplier and customer CRUD with email/phone validation. CustomersRepo.findOrCreateByChannel idempotently maps a chat identity (e.g. a WhatsApp number) to a customer record.

- **T11:** Added OrdersService: create (price snapshot, merged lines), confirm (all-or-nothing stock deduction from the chosen or default warehouse), fulfill, and cancel (restocks confirmed orders). Every transition publishes realtime events and calls status observers, which customer notifications will use.
- **T12:** Added /api/dashboard KPIs (active products, units, stock value, low-stock count, pending orders, orders today) in one SQL round trip. AlertService fires a stock.low event and chat alerts to the configured recipients only when a product's total crosses down through its reorder level.

ChannelHub routes, skips unconfigured channels, and logs every outbound message, and MessagesRepo de-duplicates inbound webhook retries by external id.
- **T14:** Added BotService for help/catalog/stock/price/order/status across every channel, with currency formatting from settings and status lookups limited to the customer's own orders. InboxService de-duplicates, logs, publishes message.received and sends the bot reply.

Payloads are parsed with permissive zod schemas, echoes and non-text messages are skipped, and webhooks fail closed (503) when secrets are unset.

Closes audit finding R2-15; T51 tests now use distinct shoppers.

The Orders page offers Mark refunded (with confirmation) on refund-due rows, and the shop order page and chat order views show refunded. - **T61** Outbox: store-then-send with retries (2026-11-26): Outbound messages are now stored first (with their message.send job in the same statement), sent immediately, and retried by the worker with backoff: retryable errors (network, 429, 5xx) keep the message queued without erroring the caller, 4xx or the last attempt marks it failed with the provider code, and a crash between store and send ends in exactly one send. Adapters return provider message ids, interactive replies are retried as interactive, and the worker starts in index.ts and drains on SIGTERM.
- **T62** WhatsApp delivery status webhooks (2026-11-26): WhatsApp delivery receipts now update outbound messages forward-only (sent, delivered, read) with failed as a terminal state that keeps the provider error code and title; replays, late receipts, unknown ids and inbound rows are ignored, forged webhooks get 401, and a message.status event is published only on real changes. Decision: a receipt that arrives before the send response stored the provider id is ignored (the message is already sent), and only failures show in the dashboard feed.
- **T63** 24-hour window and template sending (2026-11-26): WhatsApp notifications now carry a NotificationEvent: inside the 24h window they go as free-form text, outside it the template mapped in Settings is sent with ordered parameters, and with no mapping the message is stored as failed (NO_TEMPLATE) instead of silently lost. A Meta 131047 error on a free-form send falls back to the template once; bot replies and non-WhatsApp channels never use templates. Order, payment, refund and low-stock notifications are tagged with their events.

A minute-tick scheduler enqueues a task only when it is overdue per maintenance_runs, deduped across replicas, and the run results are recorded for the ops status.
